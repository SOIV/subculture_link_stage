# 캘린더 구독·피드 개선 기록

ICS 구독 메뉴, 시간대·일정 제목·알림 개선과 개인화 유예 결정의 기록이다. 과거 목표표의 미구현 표시는 당시 상태이며, 현재 응답 규칙과 남은 작업은 API 문서와 로드맵에서 관리한다.

> 2026-10-20에 기존 문서에서 이관했다. 이관일은 개별 작업일이나 재검증일이 아니다. 날짜·완료 여부·미결 상태는 원문에 명시된 범위만 보존한다. 최신 계획과 상태는 각 기획 문서와 [로드맵](../plan/11-roadmap-and-success.md)에서 관리한다.

## 2026-10-03 — ICS 시간대 개선

기록 출처: [docs/plan/08-api-and-ics.md](../plan/08-api-and-ics.md)

시간이 있는 일정에는 한국·일본 시간대의 `VTIMEZONE`을 포함하고, 그 밖의 시간대는 UTC로 변환해 보낸다(2026-10-03 구현).

## 2026-10-03 — Onstage 구독 메뉴 구현·확인 범위

기록 출처: [docs/plan/08-api-and-ics.md](../plan/08-api-and-ics.md)

- Onstage의 구독 버튼(메인, 행사 목록, 푸터)은 "Apple 캘린더 / Google 캘린더 / Outlook / 주소 복사 / 파일 받기(한 번만 추가)"를 고르는 메뉴다(2026-10-03 구현). 접속한 기기가 iPhone·iPad·Mac이면 Apple을 맨 위에 둔다. 링크 형식과 메뉴 동작은 확인했으나 Apple·Google·Outlook 앱에서의 실제 구독은 기기에서 확인하지 못했다.

## 2026-10-03 — 피드 품질 개선

기록 출처: [docs/plan/08-api-and-ics.md](../plan/08-api-and-ics.md)

2026-10-03에 다음과 같이 개선했다(`scls-platform`의 `apps/api/src/lib/ics.ts`, `public-calendar-shape.ts`).

| 항목 | 구현 내용 |
|---|---|
| 일정 제목 | `행사 이름 · 일정 종류 (대상 · 일정 이름)` — 예: `WONDERLIVET 2026 · 티켓 판매 시작 (해외 · 프리리저브 · 티켓피아)`. 일정 종류 이름은 Onstage 화면 문구와 같고 `locale`을 따른다 |
| 장소 | `LOCATION` 필드에 `장소 이름, 주소`(언어별) |
| 판매·접수 기간 | 티켓 판매·추첨 접수·참가 신청·굿즈 판매·스트리밍의 "시작" 일정은 기간(시작~끝)이 있어도 **시작 시각의 30분짜리 일정**(종일이면 시작일 하루)으로 보낸다. 몇 주짜리 긴 막대가 달력을 뒤덮는 것을 막기 위해서다. 마감은 설명에 `마감: 2026년 11월 9일 월 오후 11:59 (JST)`처럼 적는다. 행사 기간(`EVENT_START`)은 실제 기간이라 그대로 둔다 |
| 시간대 | 한국·일본은 `VTIMEZONE` 포함, 그 밖의 시간대는 UTC로 변환(Outlook 등에서 시간이 틀어지지 않게) |
| 알림 | 티켓 판매·추첨 접수·참가 신청 시작 일정에 `VALARM`: 시간이 있으면 하루 전·1시간 전, 종일 일정은 전날 오전 9시·당일 오전 9시(자정 시작이라 "1시간 전"이 한밤중이 되기 때문). 이미 끝났거나 지난 일정에는 넣지 않는다. Google 캘린더는 파일 안의 알림을 무시한다([§8.6.4](../plan/08-api-and-ics.md#864-캘린더-앱별-구독-방식)) |
| 갱신 주기 안내 | `REFRESH-INTERVAL`·`X-PUBLISHED-TTL` 6시간(참고하는 앱에 한함) |

## 2026-10-03 — 사용자 지정은 계정 도입 이후로 유예

기록 출처: [docs/plan/08-api-and-ics.md](../plan/08-api-and-ics.md)

**사용자 지정은 계정 시스템 이후로 미룬다(2026-10-03 결정).** 판매·접수 기간을 막대 / 시작만 / 시작+마감 중 고르기, 티켓 대상(국내·해외) 선택, 포함할 일정 종류, 알림 시점 지정을 계정별 설정으로 저장하고, 구독 주소는 그대로 둔 채 설정만 수정할 수 있게 한다. 계정 이전에는 주소에 옵션을 붙이지 않고(공개 API 조건으로 굳어지는 것을 피한다) 위의 기본 모양으로 고정한다.

## 구현 전 피드 품질 목표표

기록 출처: [docs/plan/08-api-and-ics.md](../plan/08-api-and-ics.md)

당시 목표와 초기 상태를 보존한 표다. 현재 구현 상태는 API 문서 §8.6.5를 따른다.

| 항목 | 당시 상태 | 당시 목표 |
|---|---|---|
| 일정 제목 | `[EVENT_START] 행사명 @ 장소`처럼 내부 코드가 보인다 | 행사명 + 일정 종류 이름(언어별) + 일정 이름(국내·해외 판매처 등) |
| 장소 | 제목 끝에 붙인다 | `LOCATION` 필드(장소 이름·주소, 언어별) |
| 시간대 | `TZID`만 쓴다(`VTIMEZONE` 없음) | `VTIMEZONE`을 포함하거나 UTC로 변환해 Outlook 등에서도 시간이 틀어지지 않게 한다 |
| 알림 | 없음 | 티켓 오픈·추첨 같은 일정에 알림(`VALARM`)을 넣는다(기본값: 하루 전과 1시간 전, 이후 사용자 지정 지원 예정). Google 캘린더는 무시한다 |
| 갱신 주기 안내 | 없음 | `REFRESH-INTERVAL`·`X-PUBLISHED-TTL`(참고하는 앱에 한함) |
| 설명 | 자동 번역 안내만 | Onstage 상세 링크, 티켓 판매처·가격 요약(선택) |
