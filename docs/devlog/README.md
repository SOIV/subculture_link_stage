# 작업 로그

기능별 변경 내용, 구현 근거, 확인 결과를 기록한다. 현재 완료 여부와 남은 일은 [로드맵](../plan/11-roadmap-and-success.md)에서 확인한다.

## 기록 목록

| 기록 | 범위 |
|---|---|
| [Phase 1 초기 구현 기록](phase-1-initial-implementation.md) | 기존 로드맵에 누적된 API·Backstage·Onstage·초기 데이터 구현 기록. 2026-10-20 이관, 개별 작업일은 본문에 명시된 경우만 확인 가능 |

## 작성 방식

- 로드맵에는 기능별 완료 여부, 짧은 현황, 남은 작업과 관련 로그 링크를 남긴다.
- 새 작업은 이 폴더의 `YYYY-MM.md`에 날짜와 작업 단위로 추가하고, 위 목록에 월별 파일 링크를 등록한다. 한 달 안에서는 최신 기록을 위에 둔다.
- 작업일을 모르면 추정 날짜를 붙이지 않고 이관 기록임을 명시한다. 기존 기록의 과거 상태를 최신 상태로 고쳐 쓰지 않고 후속 기록을 추가한다.
- 미완료 작업은 로드맵에서 관리한다. 로그에는 그 작업 당시의 남은 점을 짧게 적고 해당 로드맵 항목으로 연결한다.
- 설계·정책이 바뀌면 해당 기획 문서도 갱신하고 로그에는 변경 이유와 링크를 남긴다. Private `scls-platform`의 파일 경로는 구현 근거로만 기록한다.

## 월별 기록 예시

아래 형식으로 `YYYY-MM.md`를 만들고, 작업 규모에 따라 필요한 항목만 적는다. 아직 확인하지 않은 내용은 확인 결과로 쓰지 않는다.

```markdown
[← 작업 로그 목록](README.md) · [현재 로드맵](../plan/11-roadmap-and-success.md)

# YYYY-MM 작업 로그

## YYYY-MM-DD — 작업 제목

- 변경: 사용자에게 달라진 동작이나 완료한 내용을 적는다.
- 이유: 변경 이유나 선택 근거가 필요할 때 적는다.
- 관련: 공개 파일·기획 문서 링크 또는 Private 저장소 내 경로를 적는다.
- 확인: 실제 수행한 테스트나 수동 확인 결과를 적는다. 확인하지 않았다면 미확인으로 적는다.
- 후속: 당시 남은 점을 적고 로드맵의 관련 항목으로 연결한다.
```
