## 작성 방식

- 로드맵에는 기능별 완료 여부, 짧은 현황, 남은 작업과 관련 로그 링크를 남긴다. 아직 수행하지 않은 계획을 완료 로그로 옮기지 않는다.
- 새 작업은 이 폴더의 `YYYY-MM.md`에 날짜와 작업 단위로 추가한다. 해당 Phase와 기록 성격(구현·설계 확정·검토 중)을 표시하고, 이 목록에 월별 파일 링크를 등록한다. 한 달 안에서는 최신 기록을 위에 둔다.
- 과거 기록을 최신 상태로 고쳐 쓰지 않는다. 후속 기록을 추가하고, 현재 상태를 관리하는 기획 문서·로드맵을 갱신한다.
- 작업일을 모르면 추정 날짜를 붙이지 않는다. 이관일과 작업일, 확인한 사실과 제안을 구분한다.
- 미완료 작업은 로드맵에서 관리하고, 로그에는 당시 남은 점과 관련 항목 링크를 적는다.
- API 계약·보안 조건·운영 절차는 해당 기획 문서에 유지한다. 로그에는 선택 이유·대안·실패 사례·검증 결과를 보관한다. Private `scls-platform`의 파일 경로는 구현 근거로만 기록한다.
- 로컬 전용 초안과 취소한 제안은 `docs/local/`의 보관 원칙을 따른다. 공개 작업 로그로 자동 이관하지 않는다.

## 월별 기록 예시

아래 형식으로 `YYYY-MM.md`를 만들고 작업 규모에 따라 필요한 항목만 적는다. 아직 확인하지 않은 내용은 확인 결과로 쓰지 않는다.

```markdown
[← 작업 로그 목록](README.md) · [현재 로드맵](../plan/11-roadmap-and-success.md)

# YYYY-MM 작업 로그

## YYYY-MM-DD — 작업 제목

- 단계·성격: Phase N / 구현·설계 확정·검토 중
- 변경: 사용자에게 달라진 동작이나 완료한 내용을 적는다.
- 이유: 선택 근거나 대안 비교가 필요할 때 적는다.
- 관련: 공개 파일·기획 문서 링크 또는 Private 저장소 내 경로를 적는다.
- 확인: 실제 수행한 테스트·수동 확인 결과를 적는다. 확인하지 않았다면 미확인으로 적는다.
- 후속: 당시 남은 점과 로드맵의 관련 항목 링크를 적는다.
```
