# 02. 목표 사용자 및 기능 범위

## 2.1 목표 사용자 및 사용 사례

### 2.1.1 일반 사용자

- 관심 있는 행사 검색
- 국가, 작품, 행사 유형, 온라인 여부 등으로 필터링
- 한국어·일본어·영어 중 원하는 언어로 행사 정보 확인
- Google Calendar 또는 ICS 캘린더 구독
- 예매 시작, 추첨 마감, 공연 시작, 스트리밍 종료 알림 수신
- 잘못된 번역 또는 행사 정보 수정 요청
- 작품명·인명·티켓 용어 등 용어집 등록 제안

### 2.1.2 관리자 및 검수자

- 자동 수집 후보 검토
- 신규 행사 및 일정 승인
- 기존 행사 변경 제안 비교
- 취소·연기·출연자 변경 등 긴급 변경 처리
- 자동 번역 검수
- 사용자 번역 수정 요청 처리
- 용어집 제안 승인·병합·거절
- 수집 소스 및 행사 시리즈 관리

### 2.1.3 행사 측 담당자 (행사 관리자)

Backstage에 제한적으로 접근하는 외부 사용자군. 일반 사용자(§2.1.1)나 내부 관리자(§2.1.2)와 신뢰 수준이 달라 별도 카테고리로 둔다.

- 행사 관리자 대표: 자기 행사에 속한 하위 계정 조회·제거
- 행사 관리자 하위 계정: 자기 행사 데이터에 한해 수정 제안 제출 (제안은 change_proposals 파이프라인을 거쳐 내부 검수 후 반영, 즉시 공개 반영 아님)
- 신규 계정 등록은 대표도 할 수 없고 루트 관리자만 가능 — 대표가 임의로 팀을 확장하지 못하도록 의도적으로 제한
- 로그인 방식은 자유(소셜/이메일 등 무관) — 보안 경계는 로그인 수단이 아니라 event_id 단위 권한 부여 절차에 있음

구체적인 인증/권한 부여 절차는 [07-admin-dashboard.md §7.6 인증 및 권한 구조](07-admin-dashboard.md#76-인증-및-권한-구조) 참고. 이 카테고리는 아직 로드맵 Phase에 배치되지 않은 신규 범위이며, 배치 시점은 미결이다.

### 2.1.4 외부 서비스 개발자

- REST API 또는 향후 GraphQL API를 통한 행사 검색
- ICS 피드 사용
- Discord Bot, 웹 위젯, 개인 앱 등에서 행사 데이터 활용
- 변경 이벤트 또는 알림용 Webhook/Feed 연동(후기 단계)

현재 이 카테고리의 사용자는 이미 각자 개인 앱을 만들어 쓰고 있는 경우가 있고, 공식 API가 없어 매번 개별적으로 정보를 확인해야 하는 상태다. 다만 이런 개인 앱들은 대부분 국내(한국) 행사에 한정되어 있어 일본·해외 행사까지 함께 다루는 사례는 찾기 어렵고, 캘린더에 바로 구독 가능한 ICS 피드를 제공하는 서비스는 사실상 없는 수준이다. OpenAPI 공개는 이 사용자층을 위한 것이며, 자세한 공개 일정은 [08. SCLS API 및 ICS 설계 §OpenAPI 공개 전략](08-api-and-ics.md#85-openapi-공개-전략)과 [11. 로드맵](11-roadmap-and-success.md) 참고. 시장 차별점에 대한 자세한 내용은 [01-overview-and-principles.md §1.6 운영 형태 및 공개 정책](01-overview-and-principles.md#16-운영-형태-및-공개-정책) 참고.

## 2.2 기능 범위 정의

### 2.2.1 Core MVP 기능 (Phase 1)

행사 데이터를 수동으로 등록·관리하고 API/ICS로 외부에 제공하는 최소 단위. 수집·번역 자동화는 포함하지 않는다.

- 관리자 로그인 (인증 방식 확정 필요 — [07-admin-dashboard.md §관리자 인증 방식](07-admin-dashboard.md) 참고)
- 행사 시리즈 등록·관리
- 행사·일정 수동 등록·수정
- 장소, 주최사, 태그 관리
- 행사, 일정, 장소, 태그 관계형 DB 구축
- 한국어·일본어·영어 현지화 테이블(수동 입력 기준, 자동 번역 제외)
- 공개 읽기 API
- 전체 ICS 피드
- 행사 상세 웹페이지

> **범위 메모**: 위 항목이 모두 한 번에 "MVP"로 묶여 있다 보니 실제로는 적지 않은 작업량이다. 파일 분리 이후 세부 구현 계획을 짤 때, 이 중 우선순위를 다시 나눌지(예: 관리자 UI를 먼저 최소 기능으로 두고 이후 다듬는 식) 여부는 아직 미정이며 구현 착수 직전에 결정한다.

### 2.2.2 수집 및 번역 확장 기능 (Phase 2~3)

Core MVP가 실제로 사용된 이후 순차적으로 확장하는 자동화 범위.

- 수집 소스 및 수집 규칙 등록
- 공식 웹사이트 1~2개 자동 수집
- 수집 문서 원본 저장 및 해시 중복 검사
- 신규 후보 및 변경 후보 생성(Change Proposal)
- 관리자 승인·거절·보정
- 원문 스냅샷 및 변경 비교
- 자동 번역 생성 및 자동 번역 표시
- 번역 출처·상태 구분, 원문 리비전 기반 OUTDATED 처리
- 기본 용어집 적용
- 국가·카테고리별 ICS 피드
- **(신규)** OpenAPI 스펙 및 API Docs 페이지 개발 착수 — 자세한 내용은 [08-api-and-ics.md](08-api-and-ics.md) 참고

### 2.2.3 초기 확장 기능 (Phase 4~5)

- 공식 SNS API 또는 허용 가능한 피드 연동
- 예매처·스트리밍 플랫폼 수집
- 사용자 행사 제보
- 사용자 번역 수정 요청
- 사용자 용어집 제안
- Discord Bot API 연동
- 태그 및 작품/IP 검색
- 수집·분석·번역 작업 큐
- 오브젝트 스토리지에 HTML, JSON, 포스터 보관
- 관리자 검수 통계 및 오류 유형 집계

### 2.2.4 후기 확장 기능

- 사용자 계정 및 개인 구독
- 관심 작품·행사 시리즈·출연자별 알림
- 사용자별 ICS 피드
- 고신뢰 출처 자동 승인
- 다국어 전문 검색
- 임베딩 기반 유사 문서 검색
- 변경 Webhook 또는 SSE 제공
- API Key 및 외부 개발자 콘솔 (호출량 상향, Webhook 구독 등 심화 기능 — 기본 공개 문서/조회는 Phase 3에 이미 공개됨)
- 신뢰 기여자·번역 검수자 권한
- 공개 기여 이력 및 기여자 프로필

### 2.2.5 초기 제외 또는 제한 기능

- SNS 전체 이미지·영상 무제한 보관
- 비공식 루머 및 출처 불명 행사 등록
- 사용자 수정 내용의 즉시 공개 반영
- 투표만으로 번역 또는 공식 데이터를 확정하는 기능
- 초기부터 모든 행사·지역·플랫폼을 포괄하는 대규모 수집
- 처음부터 자체 번역 모델을 학습하는 작업

## 2.3 초기 대상 범위

### 2.3.1 국가 및 형태

- 한국
- 일본
- 글로벌 온라인 스트리밍

### 2.3.2 초기 행사 유형

- 게임·애니메이션 종합 행사
- 성우·아티스트 라이브
- 팬미팅
- 온라인 유료 스트리밍
- 티켓 추첨·판매 일정

팝업스토어, 콜라보 카페, 굿즈 판매, 극장 상영은 데이터 구조가 안정된 이후 확대한다.

### 2.3.3 초기 대상 행사 시리즈 (확정)

- AGF Korea (Anime Game Festival Korea)
- 코믹월드 (서울 코믹월드, 부산 코믹월드 등 지역별 개최분 포함)
- 지스타 (G-STAR)
- 플레이엑스포 (PlayX4)
- 일러스타 페스 (ILLUSTAR FES)
- TGS (Tokyo Game Show)
- COMIC MARKET (코미케)
- AnimeJapan
- WONDERLIVET (J-POP & Iconic Artist 뮤직 페스티벌)

선정 기준은 수집 가능성, 공식 출처 안정성, 실제 사용 빈도다. 코믹월드처럼 지역별로 개별 개최되는 시리즈는 Event Series 단위를 지역별로 나눌지, 하나의 Series 아래 지역별 Event로 묶을지 구현 착수 시 결정한다.

BanG Dream!, Project SEKAI, 주요 게임사 공식 쇼케이스 등은 이번 선정에서 제외했다. 이 중 반복 투어형 시리즈(하나의 Series 아래 다수의 Event/Schedule이 반복 생성되는 구조)는 데이터 모델 검증 목적으로 Phase 1 후반~Phase 1.5 즈음 1~2개만 별도로 추가 검토한다. 그 외 행사는 추후 별도 조사로 확대하며, 이 목록은 최종 커버리지가 아니라 초기 10개 선정의 기준선이다.
